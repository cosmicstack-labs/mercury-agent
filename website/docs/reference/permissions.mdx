Mercury has a layered permission system that controls what actions the agent can take. The behavior differs significantly between **Ask Me** and **Allow All** modes.

## Permission Modes

At session start, Mercury asks you to choose a permission mode:

- **🔒 Ask Me** — Mercury asks for confirmation before risky actions. Default on both CLI and Telegram.
- **✅ Allow All** — Mercury skips ordinary action prompts for this session. Hard blocks and filesystem scopes still apply.

On **CLI**: an arrow-key menu appears at startup before the first prompt.

On **Telegram**: inline keyboard buttons appear with the first message. Use `/permissions` to change mode at any time.

**Scheduled tasks** always run in Allow All mode — filesystem access and shell commands are auto-approved.

### How Modes Differ

| Action | Ask Me | Allow All |
|--------|--------|-----------|
| File reads | Auto-approved (via scope matching) | Auto-approved |
| File writes | **Always prompts** | Auto-approved (via scope matching) |
| Safe shell commands (`ls`, `cat`, `grep`, `git status`) | Auto-approved | Auto-approved |
| Other shell commands | **Prompts** | Auto-approved |
| New directory scope | **Prompts** | Auto-approved |
| Loop continuation | **Prompts** | AI self-check (Mercury Autopilot) |

### "Always" Response

Choosing **"Always"** remembers the relevant approval for this interaction; it does not turn on Allow All. Shell approvals can cover a command family on local channels, while web requests retain the exact approved command. Hard-linked file writes have a separate approval from reads.

## Shell Command Tiers

### 1. Blocked (never executed)

Commands like `sudo`, `rm -rf /`, `mkfs` are never executed regardless of mode.

### 2. Commands eligible for automatic approval

Simple commands such as `ls`, `cat`, `head`, `tail`, `grep`, `rg`, and selected `git` read operations can run without a prompt when their arguments pass the command policy. Mercury executes them directly with a pinned executable and a minimal environment. Pipelines, shell expansion, side-effect flags, and commands outside this policy require approval.

The argument check resolves existing relative filenames and symlinks against the tool's current working directory, and checks canonical targets against the working directory and readable scopes. In Ask Me mode, an explicit hard-linked operand requires command approval because another alias may lie outside those scopes. Recursive link-following flags, such as `rg --follow`, `grep -R`, and `find -L`, also leave the automatic-approval lane. Explicit owner command grants and Local Allow All retain their existing approval behavior.

### 3. Everything Else

- **Ask Me mode**: Prompts for approval. Approval options: Yes / No / Always.
- **Allow All mode**: Auto-approved (except blocked commands).

Edit `~/.mercury/permissions.yaml` to customize blocked and auto-approved command patterns. Skill elevation: skills with `allowed-tools` in their SKILL.md get automatic approval for those tools during execution.

## File System Scopes

Mercury uses directory scopes to control file access. When the agent tries to access files in a new directory:

- **Ask Me mode**: Prompts for scope approval (reads and writes)
- **Allow All mode**: Existing filesystem scopes still determine access

Filesystem tools check the configured scopes. The shell's automatic-approval lane also permits its working directory. Moving a shell's working directory is not an OS-level sandbox operation.

`write_file` and `edit_file` retain the canonical target and file identity from before approval. They open without truncating, verify the opened descriptor and link count, then modify that descriptor. A replacement during approval is refused, and nonblocking opens prevent a replacement FIFO from hanging the write. A hard-linked file needs its own write approval because modifying it changes every alias. `create_file` records an existing canonical ancestor before approval and revalidates the parent chain before creating directories. It creates the file exclusively, so a file planted at the destination cannot be overwritten.

### Security boundary

These are application permission checks, **not an OS sandbox**. An approved shell command, a bot's explicit command grant, or an elevated tool runs with the Mercury process's operating-system privileges. A script can access files through its own logic; recursive commands can encounter hardlinks that were not explicit operands. Argument checks do not mediate every file opened by a child process, nor prevent a hostile process from racing directory or link changes after a check. Verified writes protect the captured existing file; parent checks followed by directory/file creation are not an atomic directory-relative sandbox operation; a separate OS process can still race those steps after validation.

Use an independently configured OS sandbox or container when running untrusted programs. Mercury does not currently supply a portable Linux/Windows kernel-isolation mode, and it must not describe permission scopes as one. Native junction/hardlink tests run in the existing Windows CI matrix; passing Linux tests alone does not establish Windows runtime results.

## Mercury Autopilot (Loop Detection)

Mercury includes an intelligent loop detection system called **Mercury Autopilot** that prevents the agent from getting stuck in repetitive tool call patterns.

### How It Works

Instead of simply counting repeated tool calls, Autopilot analyzes:

- **Parameter diversity** — Are the arguments changing between calls, or is it calling the same thing over and over?
- **Success rate** — Are the calls succeeding or failing repeatedly?

This produces a verdict:

| Verdict | Criteria | Action |
|---------|----------|--------|
| **Productive** | Diversity ≥ 60%, success ≥ 70% | Continue without interruption |
| **Suspicious** | Between productive and stuck | Monitor (Allow All: AI self-check, Ask Me: prompt user) |
| **Stuck** | Low diversity and/or low success | Stop the current execution path |

### AI Self-Check (Allow All Mode)

In Allow All mode, when Autopilot detects suspicious patterns, it asks the AI model itself to evaluate whether it's making progress. The AI sees its recent tool calls and decides whether to continue or stop. This runs up to 3 times before Autopilot forces a stop.

### User Prompt (Ask Me Mode)

In Ask Me mode, suspicious patterns trigger a user prompt asking whether to continue. On Telegram, this appears as an inline keyboard with Continue / Stop buttons.

### Hard Limits

Regardless of mode, Mercury enforces absolute limits:

| Limit | Value | Description |
|-------|-------|-------------|
| Max steps per task | 25 | Normal tool call limit |
| Absolute max | 75 | Hard ceiling (never exceeded) |
| Failed absolute max | 20 | Max steps if all are failing |
| Max self-checks | 3 | AI self-check attempts before forced stop |

All Autopilot messages are branded with `☿ Mercury Autopilot` for easy identification.
